# Pr-Workflow — 커밋 & PR 생성 절차

커밋 메시지 작성부터 PR 템플릿 본문, gh CLI로 PR을 올리는 순서까지의 절차.

> 규칙 기준: `CLAUDE.md` §6(워크플로우), §9(PR 품질 기준).

## Step 1: 커밋 단위 확인

의미 있는 논리적 단위인지 먼저 확인한다 — 한 커밋에 서로 다른 관심사(기능 추가 + 무관한 리팩터)를 섞지 않는다. 단위가 애매하면 나누는 안을 먼저 제안하고 사용자 확인을 받는다. 최근 히스토리가 좋은 기준이다: `refactor: 주간 랭킹 평가 로직 단계별 메서드로 분리` 같은 단일 관심사 커밋.

## Step 2: 커밋 타입 — 허용 목록

`.husky/commit-msg`가 접두사를 검사한다. **이모지 없이** 아래 타입으로 시작 + **한국어 요약**:

| 타입 | 용도 |
|---|---|
| `feat:` | 새 기능 |
| `fix:` | 버그 수정 |
| `refactor:` | 동작 변경 없는 구조 개선 |
| `style:` | 스타일/포맷팅(로직 무변경) |
| `docs:` | 문서 |
| `chore:` | 잡무(설정, 의존성 등) |
| `rename:` | 파일/식별자 이름 변경 |
| `remove:` | 코드/파일 삭제 |
| `test:` | 테스트 추가/수정 |
| `ci:` | CI 설정 |
| `lint:` | 린트 규칙/수정 |

예: `fix: 6번째 스텝에서 최종점검으로 넘어가면 헤더에 하트가 안뜨던 버그 수정`

chaen 레포의 이모지 프리픽스(`✨ feat:`)를 이 레포에 가져오지 않는다 — 훅이 거부한다.

## Step 3: 훅 통과

- `pre-commit`: lint-staged(prettier --write + eslint --fix). 실패하면 원인을 고친다.
- `pre-push`: lint → check-types → build 순차 실행 — 몇 분 걸릴 수 있다. **실패 시 `--no-verify`로 우회하지 않고** 원인을 고치거나, 기존 코드 문제면 사용자에게 보고한다(CLAUDE.md §10-5).

## Step 4: 브랜치·PR 준비

- 브랜치명: `type/topic` (예: `refactor/ranking-evaluation`, `feat/quiz-review`). base는 **`develop`**.
- 푸시 전 로컬에서 검증을 이미 돌렸다면 pre-push와 중복 실행을 피하려 하지 말 것 — 훅은 그대로 둔다.

## Step 5: PR 본문 — 템플릿 준수

`.github/pull_request_template.md`의 6개 섹션을 전부 한국어로 채운다:

```markdown
## ⏱ 소요 시간          ← 사용자만 아는 정보 — 빈 칸으로 두고 채워달라고 알린다
## 📌 작업 요약          ← 한두 문장
## 📝 작업 내용          ← 번호 목록, 필요 시 이미지
## 🚨 주요 고민 및 해결 과정  ← ### 문제 / ### 해결 과정
## 📑 참고 문서/ ADR     ← HEADSON.md Phase 해당 시 링크. 없으면 "없음"
## 💬 리뷰 요구사항       ← 없으면 "없음"
```

검증 관련 서술은 **실제로 실행한 명령과 결과만** 적는다 — 실행하지 않았으면 "미실행"이라고 정직하게 적는다.

## Step 6: PR 생성

```bash
gh auth status                       # 이 레포(boostcampwm2025/web21-funda)에 권한 있는 계정인지 확인
gh pr create --base develop --title "{type: 한국어 요약}" --body "{Step 5 본문}"
```

PR 제목은 대표 커밋과 같은 `type: 한국어 요약` 형식.

## 자가 확인

- [ ] 커밋 메시지가 허용 타입(이모지 없음)으로 시작하고 한국어인가?
- [ ] 커밋이 하나의 논리적 단위인가? 무관한 변경이 섞이지 않았는가?
- [ ] 훅을 우회(`--no-verify`)하지 않고 통과시켰는가?
- [ ] PR 본문이 템플릿 6개 섹션을 전부 채웠는가(빈 섹션 없음)? 검증 서술이 실제 실행 결과인가?
- [ ] base가 `develop`인가? 제목·본문이 한국어인가?
